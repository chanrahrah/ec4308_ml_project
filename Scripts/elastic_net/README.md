# Logistic Elastic Net models in R

This package follows the baseline project's modular layout: `config.R`, `models.R`, `portfolio.R`, `tests.R`, `report.R`, and one entry script, `run_elastic_net.R`. It predicts whether equities outperform maturity-matched Treasury bills at **h = 1, 3 and 6 months**, using **132 predictors**, the teacher's Elastic Net penalty, **40 fixed hyperparameter combinations**, and a **0.05-step trading cutoff grid**.

This is a structural reorganization of `EC4308_elastic_net_logit_fixed03_cutoff005_full_pipeline.R`. The configuration and fitting, tuning, portfolio, diagnostic and report functions are preserved. Changes concern module loading, project-path detection, hashes for all six R files, a separate output folder and package-version export. It does not convert the Elastic Net into the baseline's five-variable model, or change its cutoff step to the baseline's 0.01.

Earlier test results were inspected during project development. This is an exploratory sensitivity specification, not a new untouched holdout study.

## Model and penalty convention

The probability model is:

`P(Y_(t,h)=1 | I_t) = logistic(b0_h + X_t' beta_h)`.

Each horizon has its own model and selected settings. Estimation minimizes:

`mean negative binomial log-likelihood + lambda * sum_j[rho * beta_j^2 + (1-rho) * abs(beta_j)]`.

The intercept is unpenalized. In the script and output CSV files, **`alpha` denotes the teacher's rho**: alpha = 0 is Lasso; alpha = 1 is Ridge. Internally the exact conversion to glmnet's convention is:

- `alpha_glmnet = (1-alpha)/(1+alpha)`;
- `lambda_glmnet = lambda*(1+alpha)`.

These conversions preserve both the L1 and L2 penalty coefficients. The intermediate glmnet warm-start path is a numerical fitting device, not an extra hyperparameter search.

## Splits, hyperparameter tuning and expanding refits

Initial training uses the existing historical model data and the December 2004 boundary. Validation origins are January 2005–December 2012; test origins are January 2013–December 2025. At every monthly origin t, the training sample expands to include only earlier observations whose outcomes have completed by t. Previously purged rows enter once mature. Centering and sample standard deviations are recomputed on those fitting rows only.

The fixed grid is identical across horizons, mixing parameters and monthly refits:

| Parameter | Values |
| --- | --- |
| Teacher alpha/rho | 0, 0.25, 0.50, 0.75, 1 |
| Fixed absolute lambda | 0.0001, 0.0005, 0.002, 0.01, 0.05, 0.10, 0.20, 0.30 |

This is **5 × 8 = 40 combinations per horizon**. For each combination, validation probabilities are generated through 96 monthly expanding refits. Predictive selection minimizes the mean validation Brier score `(p-y)^2` on completed, eligible labels. The 1-SE rule is not applied. Ties within 1e-12 prefer fewer average nonzero slopes, then larger lambda, then smaller teacher alpha.

The lambda upper bound 0.3 is a prespecified practical search limit; it is not computed from each training set's maximum zero-coefficient threshold. Gradient and zero-threshold diagnostics do not determine the fixed candidate grid.

Fitting minimizes penalized negative log-likelihood. Brier score selects hyperparameters after forecasting; it is not the training objective.

## Cutoff selection and test forecasts

For the selected hyperparameters, search **0.00, 0.05, ..., 1.00** (21 cutoffs). `p >= cutoff` selects equities; otherwise select bills. Choose the cutoff maximizing validation monthly **net matched-ladder Sharpe at 10 bp**. Undefined values are excluded; all-undefined candidates cause a stop. Ties within 1e-12 choose closest to 0.50, then the lower cutoff.

Freeze the hyperparameters and cutoff for every horizon before producing final-test forecasts. In test, refit coefficients and scaling monthly, keeping selected hyperparameters and cutoffs fixed. Also report the fixed-0.50 rule using the same probabilities. Signals remain fixed across the 0/10/20 bp cost comparisons.

Classification metrics exclude target windows crossing the evaluation boundary. The supplied data have 95/93/90 eligible validation labels and 155/153/150 eligible test labels for h=1/3/6. Forecasts are still produced at all 96 validation and 156 test origins per horizon, including origins with incomplete evaluation targets. The recursive historical-prevalence benchmark uses exactly the same mature training labels as the model.

## Overlapping portfolios and transaction costs

Each signal determines an h-month position. Active cohorts receive equal post-cost capital monthly. The first h-1 signals initialize the portfolio; scored returns start February/April/July for h=1/3/6. Validation ends in December 2012 and test ends in December 2025. Benchmark comparisons use identical months within each horizon. `common_window_performance.csv` additionally restricts all horizons to their shared evaluation window.

Stocks earn CRSP value-weighted total returns. Each bill vintage accrues its origin's matched daily log yield over the actual number of days between adjacent monthly quote dates: `expm1(origin_yield * days)`. The 3/6-month bill benchmark is a ladder of historical yields. This is an idealized accrual proxy: interest-rate mark-to-market changes and bill-transfer frictions are not modeled.

Let V be wealth before rebalancing, S existing stock value, w target stock weight and c one-way transaction cost. Net stock trade q solves `q = w*(V-c*abs(q))-S`. Purchases use `(w*V-S)/(1+c*w)`; sales use `(w*V-S)/(1-c*w)`. This captures both allocation changes and drift rebalancing. Initial allocation is endowed with no fee. There is no separate bill-leg fee or final liquidation fee.

Comparators are all stocks, all matched bills, and a monthly rebalanced 50/50 stock–bill portfolio. Results are reported at 0, 10 and 20 bp costs.

## Performance measures and interpretation

- `sharpe_common_rf`: monthly net portfolio returns minus the common 4-week bill accrual reference.
- `sharpe_matched_ladder`: monthly net returns minus the horizon-specific all-bill ladder return. This selects the cutoff.
- `net_Sharpe`: compatibility alias for matched Sharpe.
- Both Sharpe measures use `sqrt(12) * mean(excess) / sd(excess)`.
- Maximum drawdown uses the monthly net wealth path, including initial wealth 1, and is not annualized. Intramonth drawdowns are unobserved.

All-bill matched excess returns have zero volatility, so their matched Sharpe is undefined. A bill-ladder Sharpe against the common reference reflects yield-spread variation under the accrual proxy.

An intercept-only fit has zero predictor coefficients and forecasts the mature training sample's equity-outperformance frequency. Such a fit produces buy-and-hold equity exposure only if its probability stays above the chosen cutoff. A positive Sharpe alone is not evidence of predictive or timing gains.
